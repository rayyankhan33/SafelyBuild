| Tool | Used for | Output reviewed by |

**Process note for the supervisor.** A large amount of code arrived in a few working sessions. ## 2. Runtime AI and models

| Component | Source | Notes |
|---|---|---|
| `classical_color` (stage, stock) | Hand-written OpenCV colour and geometry logic (`scene.py`) | No learned model. Validated on synthetic frames only |
| `opencv_tiles` (defects) | Team's POC heuristics (`heuristics.py`) | No learned model; tuned on 4 photos |
| `yolo_world` (optional) | Ultralytics YOLO-World `yolov8s-worldv2` (about 26 MB) with the OpenAI CLIP ViT-B/32 text encoder (about 338 MB), zero-shot, pretrained by others | Installed on the development machine on 2026-10-13 with the team's approval; **not active**. Smoke-tested only: found nothing at the default threshold on the 4 sample photos and no steel at any threshold, so it is not used. Weights are git-ignored and never downloaded by the project's code. Accuracy on site footage unmeasured |
| `crack_cnn`, `tiles_and_cracks` (defects, opt-in) | MobileNetV3-Large (torchvision, ImageNet-pretrained weights from download.pytorch.org) fine-tuned in this repository on SDNET2018; weights `services/inference/models/crack_cnn.onnx` (16.8 MB, committed on purpose) | Trained by Rayyan's machine with code written by Claude Code (2026-10-12/13). Measured results and limits in [crack-model.md](crack-model.md). Runs locally through OpenCV; PyTorch is training-time only. **Not active by default** |
| Trained model (teammate) | In progress, to be added as a plugin | See [model-integration.md](model-integration.md) |
| Synthetic demo frames | Generated by `demo_frames.py` (drawn with OpenCV, plus lightly perturbed copies of the 4 real sample photos for the inspection camera) | **Not real images.** Used only for demos and tests; the project is flagged `is_demo` and the UI says so |

No external AI service is called at runtime. Frames never leave the machine running the inference service.

## 5. Data and privacy

- Demo data is fictional. The demo password is for local use only (see demo-accounts.md).
- Real deployments will hold site frames (which may show workers), possibly GPS, and financial figures. They need HTTPS, encrypted storage, a retention policy, worker notice and consent for monitoring, and a policy for who may view frames. None of these exist yet.
- Camera keys are stored only as SHA-256 hashes; the audit log records user IDs and actions, not frame content.
- Continuous camera monitoring of workers is sensitive; the system measures materials, structures and defects, not individuals, but frames can incidentally show people.
